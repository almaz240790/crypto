# Platform — сервис торговых сигналов на H4 (крипта)

Продуктовый план и техническое задание: `docs/product-plan.md`. Любая задача ссылается на раздел плана.
Решения по архитектуре фиксируются в `docs/adr/`.

## Структура репозитория

```
packages/engine/   Python-пакет `engine`: сигнальный движок, индикаторы, паттерны, бэктест, загрузка данных.
                   Чистая логика без веба и без сети (кроме engine/data — загрузчики истории).
apps/api/          FastAPI: HTTP/WS API, модели БД (SQLAlchemy 2), миграции (Alembic), воркеры.
apps/web/          Next.js (этап 2, пока нет).
packages/charts/   TypeScript-график (этап 2B, пока нет).
infra/             docker-compose, конфиги окружений.
scripts/           Служебные скрипты (загрузка истории, проверки данных).
docs/              План, ADR, отчёты бэктестов.
```

## Команды

```
make setup        # uv sync для всех пакетов + pre-commit install
make lint         # ruff check + ruff format --check + mypy
make test         # pytest по всем пакетам
make up           # docker compose: Postgres+Timescale, Redis, API
make migrate      # alembic upgrade head
make load-history # загрузка истории свечей с Binance (см. scripts/load_history.py --help)
```

## Правила (обязательные)

Движок и данные:
- Все расчёты в `engine/` — только по **закрытым** свечам. Незакрытая свеча никогда не попадает на вход движка.
  Любая функция, которая берёт свечи, принимает уже отфильтрованный список; тест на «утечку будущего» обязателен для каждого правила.
- Цены и объёмы — `Decimal` в хранении и API; в расчётах индикаторов допускается `float`/numpy, но вход и выход движка — `Decimal`.
- Время — только UTC, timezone-aware `datetime`. `open_time` свечи = начало интервала.
- `engine/` не делает сетевых вызовов и не знает о БД. Исключение — `engine/data/` (загрузчики истории), и он не импортируется из остального движка.
- Параметры стратегии меняются только через новую версию стратегии. В коде нет «магических чисел» — всё в `StrategyParams`.
- Таблица `signals` — insert-only по торговым полям (триггер в БД). Статусы — только через `signal_events`.
- Одна кодовая база для live, forward и backtest. Функция `replay()` должна воспроизводить сигнал бит в бит.

Код:
- Python 3.12+, `uv`, `ruff` (lint + format), `mypy --strict` для `engine/`. Покрытие тестами `engine/` ≥ 90 %.
- Один PR — одна задача из плана (раздел 10.3). В описании PR: номер задачи, что сделано, как проверено, что неясно.
- Conventional Commits: `feat:`, `fix:`, `docs:`, `test:`, `chore:`, `refactor:`.
- Перед коммитом: `make lint test`.
- Секреты только в `.env` (в `.gitignore`); пример — `.env.example`.

Дизайн и тексты (для `apps/web`, этап 2):
- Токены цветов и шрифтов — только из дизайн-системы (план, раздел 5). Произвольные цвета запрещены ESLint-правилом.
- Запрещённые формулировки: обещания доходности, «ИИ предсказывает», «сигнал на покупку» для паттернов (план 2A.10.6, 5.2, 8).

## Что требует подтверждения человека

Логика сигналов и паттернов (20 примеров на правило), результаты бэктеста, деньги (платежи, тарифы), юридические тексты,
промпты LLM, выпуск стратегии или модели в live, деплой в production. Полный список — план, раздел 10.4.
Fable 5 / Claude не получает боевых ключей платёжного провайдера, кошельков, бирж и доступа к production-БД.
