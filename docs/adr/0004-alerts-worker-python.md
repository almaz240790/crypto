# ADR-0004: воркер алертов на Python, а не на Node

Статус: принято (2026-10-27). Задача 2B.13, план 2A.6 и раздел 6.

## Контекст

План (раздел 6) предлагал `alerts-worker` на Node.js с библиотекой индикаторов `packages/charts`,
чтобы использовать тот же код, что и клиент. К моменту 2B.13 все воркеры (market-data, scheduler,
tracker, notifier, pattern-detector) — Python в `apps/api`, с общими моделями БД, доставкой
уведомлений (`app/notify.py`, `app/push.py`) и движком `engine/`. Индикаторы TS и Python проходят
общий golden-набор с точностью 1e-8 (2B.3), поэтому результат одинаков.

## Решение

`app.workers.alerts` на Python: подписка на `candles.closed`, проверка условий функциями
`app/alerts.py` (цена по 1m, индикаторы/зоны/структура по закрытию свечи TF, паттерны по новым
записям `patterns`), запись в `alert_triggers` с уникальностью `(alert_id, triggered_at)`, доставка
через существующие push/email с настройками пользователя (тихие часы, дневной лимит).

## Последствия

- Один язык и одна кодовая база для всех воркеров; нет дублирования доставки и моделей.
- Расчёт индикаторов — `engine/indicators.py` (эталон для TS), расхождений с клиентом нет.
- Алерты по рисункам (v2) при необходимости потребуют геометрии из `packages/charts` — это
  отдельное решение; при появлении Node-воркера он сможет жить рядом.
