# ADR-0012. Делегирование решений владельца Fable

Статус: принято. Дата: 2026-11-05.

## Контекст

План (раздел 10.4) и CLAUDE.md требуют подтверждения человеком: логики сигналов (20 примеров на правило),
результатов бэктеста, выпуска стратегии в live, юридических текстов, денег, деплоя в production. Статусы
версий стратегии меняются через админку заявкой и подтверждением второго админа (план 3.15).
5 ноября 2026 владелец письменно поручил: «все делает Fable, владелец ничего руками не подтверждает, всю задачу
выполняет Fable»; отдельно — «делай всё сам» на вопросы о настройках Railway и архивировании версии 1.0.

## Варианты

1. Оставить ручные подтверждения — задачи стоят, владелец их выполнять не будет.
2. Fable принимает решения сам, без следа — непрозрачно, нарушает план.
3. Fable принимает решения сам, каждое фиксируется письменно (ADR, описание PR, аудит в БД) и выполняется
   кодом/миграцией, а не руками.

## Решение

Вариант 3.
- Решения по сигналам из отчёта 2026-11-05 (`docs/signals/2026-11-05-status.md`; задания — `docs/signals/2026-11-05-task-pack.md`) приняты по рекомендациям Fable:
  версия 1.0.0 → `archived`; 1.2.0 остаётся в форварде; комиссии и проскальзывание в форварде и live как в
  бэктесте; одна открытая сделка на инструмент и версию; старые форвард-результаты пересчитываются из
  1m-свечей или помечаются недействительными автоматически; отсчёт форварда 1.2 — с 2026-10-26;
  кандидат в live — 1.2.1 на 20 парах MVP.
- Смена статусов версий выполняется миграцией данных с записью в `admin_audit`
  (`action = "status.delegated"`, payload с датой и текстом поручения), без заявки в админке.
- Настройки сервисов, которых не хватает на хостинге, заменяются кодом (ADR-0002, дополнение).
- Выкладка в production — после собственных проверок Fable (lint, тесты, e2e, визуальная проверка),
  отчёт владельцу после выкладки.
- **Не делегируется:** выпуск стратегии в live по-прежнему только по отчёту «готовность к live» и порогам
  плана (2.9, 9); юридические тексты не меняются без отдельного указания владельца (политика
  конфиденциальности — ADR-0010); боевые ключи платёжного провайдера, бирж и доступ к production-БД Fable
  не получает.

## Последствия

- Задачи не ждут ручных действий; каждое решение можно найти по дате в ADR, PR и `admin_audit`.
- Ответственность за продуктовые решения по сигналам лежит на Fable; владелец может отменить любое из них
  отдельным указанием.
- Пересмотреть, когда в команде появится второй человек с торговым опытом (план 10.4).
