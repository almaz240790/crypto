# ADR-0005: переводы по исходной строке без next-intl

Статус: принято (2026-10-27). План: раздел 1 («русский и английский с первого релиза»), раздел 6 («i18n: next-intl, ru/en»).

## Контекст

К моменту решения интерфейс `apps/web` (около 9 000 строк JSX, 30 страниц) написан по-русски без
слоя переводов; e2e-тесты (десятки файлов) ищут элементы по русским подписям. План предполагал
`next-intl` с ключами-идентификаторами и файлами сообщений на оба языка. Переход на идентификаторы
означал бы переписать каждую строку и каждый тест сразу, без возможности выпускать страницы
по частям.

## Решение

- Ключ перевода — сама русская строка: `t("Сигналы")`. Для `ru` функция возвращает ключ, для `en` —
  значение из `src/i18n/en.json`, а при отсутствии перевода — русский исходник (страница не
  ломается, просто остаётся по-русски). Подстановки — `t("Сделок: {n}", { n })`.
- Локаль: cookie `pl_locale` (ru/en), иначе `Accept-Language`; для вошедшего пользователя —
  поле `locale` профиля (переключатель в шапке пишет и cookie, и профиль). `<html lang>` ставится
  на сервере по той же cookie.
- Серверные компоненты берут `getT()` из `src/i18n/server.ts`, клиентские — `useT()` из
  `src/i18n/client.tsx`. Компоненты, импортируемые из клиентских (шапка, подвал), — клиентские.
- Перенос строк в `t()` делается кодмодом по файлам (текстовые узлы JSX, атрибуты `label`,
  `placeholder`, `title`, `aria-label`, строковые литералы внутри компонентов) с ручной проверкой
  результата; страницы переводятся порциями, каждая — отдельный PR с пополнением `en.json`.

## Последствия

- Плюс: русская версия и тесты не меняются (ключ = исходник), английский растёт инкрементально,
  непереведённые места видны по пропускам в словаре (можно проверить скриптом).
- Минус: при правке русской фразы нужно переименовать ключ в `en.json`, иначе перевод теряется —
  в CI стоит добавить проверку «ключи словаря встречаются в коде». Множественное число и порядок
  слов во фразах, собранных из нескольких узлов (`сделок <strong>{n}</strong>`), переводятся
  пофрагментно; такие места при необходимости переписываются на один ключ с подстановкой.
- Переход на `next-intl` остаётся возможным: словарь `en.json` переносится как есть, ключи можно
  заменить идентификаторами позже.
