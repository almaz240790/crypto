# ADR-0007. «Разбор сверху вниз»: свои правила `topdown@1.0.0`, тренд по защищённой swing-точке, секции на закрытии свечи

Статус: черновик (Claude), утверждает владелец. Дата: 2026-10-31.

## Контекст

**Задача.** ADR-0006 назвал следующей задачей панель «Разбор»: анализ сверху вниз W1 → D1 → H4 → H1 → 15m для 59 фьючерсных пар. Её надо считать на сервере и показывать на десктопе и телефоне. Логику владелец проверяет на примерах до выпуска (план 10.4). Владелец попросил не задавать ему вопросов по теханализу, поэтому правила выбраны по стандартной практике и записаны здесь вместе с замерами.

**Ограничения:**
- CLAUDE.md:
  - движок считает только по закрытым свечам;
  - Decimal на входе и выходе, время в UTC;
  - engine без сети и БД;
  - параметры меняются только новой версией;
  - один путь кода для live и replay;
  - тест на утечку будущего для каждого правила;
  - mypy --strict, покрытие ≥ 90 %.
- План: 2A.1 («график не генерирует сигналы»), 2A.10.6, 5.2 и 8 (тексты).

**Что выяснилось в коде:**
- **Модули движка.** `engine.structure`, `zones` и `indicators` не привязаны к таймфрейму, но их параметры считаются в свечах. Первое событие окна движок всегда метит как BOS.
- **Параметры чужого назначения.** `bias.compute_bias` связан с сигнальной стратегией: имена LONG/SHORT, параметры из `latest_version()`, где версия 1.2.0 с `allow_long=False` превращает «вверх» в NEUTRAL. Слои, скринер и алерты берут параметры из трёх разных источников.
- **15m и 1h.** Это только агрегаты из 1m, без проверки пропусков. В режиме REST-опроса (Binance молчит по WS на Railway) в 1m остаются вечные дыры. Секция H1 читает 30 тыс. строк 1m.
- **Прокси `/v1`.** Он пропускает только перечисленные заголовки (PASS_REQ/PASS_RES), поэтому ETag и If-None-Match не доходят.
- **Пересоздание страницы.** Ключ сегмента `[tf]` в Next 16 включает значение, и `TerminalPage` пересоздаётся при каждой смене ТФ.
- **pattern_detector.** Его слушатель обрабатывает события последовательно.

**Замеры** (архивы Data Vision BTC/ETH/SOL: W1 из D1 за 2020–2026, D1 2023–2026, H4 2025-04…2026-09, H1 2026-03…09, 15m 2026-08…09):

| Правило тренда | Смен на 100 свечей | Доля «нет тренда» |
|---|---|---|
| А. classify_trend: последние 2 максимума и 2 минимума (план 2.2) | 12–15 | ≈ 40 % |
| Б. classify_trend И направление последнего пробоя | 10.5–12.4 | 48–60 % |
| В. Защищённая swing-точка | 1.7–6.8 | 4–15 %; повторные входы на тех же точках — 0.2–0.5 на 100 |
| Г. В + повторный вход только после новой swing-точки | 1.7–6.1 | 4–17 % |

| Направление старших ТФ (по дням) | Смен на 100 дней | Есть направление | W1 против D1 | У D1 нет тренда |
|---|---|---|---|---|
| Тренд D1 (Г), вето W1, EMA — только подпись | 3.4–5.9 | 54–58 % | 25–38 % | 8–17 % |
| То же плюс условие close D1 vs EMA50 (как bias 2.2) | 6.8–9.1 | 52–59 % | 19–29 % | 20–27 % |

Состояние Г на последней свече окна в 500 свечей совпало с расчётом по всей истории в 40 из 40 случайных срезов на D1, H4, H1 и 15m. Расчёт секции на 1000 свечах занимает около 13 мс.

## Варианты

1. **Тренд по таймфрейму:** А, Б, В или Г из таблицы. А и Б меняют состояние почти каждые 8–10 свечей и половину времени показывают «флэт» или «диапазон», то есть обычный откат внутри тренда выглядит как его отсутствие. В даёт ложные повторные входы, и это противоречит тексту «держится, пока нет закрытия ниже границы».
2. **Направление старших ТФ:**
   - а) bias плана 2.2 с EMA50 D1 — тогда область интереса пропадает как раз на откатах под EMA50, когда цена приходит в зону H4;
   - б) тренд D1 с вето W1, EMA50 показывается как уточнение («под EMA50»).
3. **Младшие ТФ:**
   - а) статус «цена в зоне H4 + пробой структуры на H1/15m после касания» — по сути это триггер входа, а с «совпадают 5 из 5» — готовый сетап без бэктеста рядом с сигнальным продуктом;
   - б) только собственные факты H1/15m и зоны H1/15m внутри зоны H4.
4. **Расчёт и хранение:**
   - а) на запрос, как `/layers` — кэш без времени закрытия смешивает свежие и старые ТФ;
   - б) секции на закрытии своего ТФ, сводка — при чтении;
   - в) то же плюс таблица сводок каждые 15 мин — сложнее: дедлайны и «вечно устаревшие» insert-only строки.
5. **Свечи 15m/1h:**
   - а) агрегаты 1m с проверкой полноты — неполные свечи дают ложные swing-точки, обрезка по пропуску гасит секцию на сутки;
   - б) нативные 15m/1h в market_data — существующий бэкфилл сразу даёт 1500 свечей.
6. **Где считать:**
   - а) шаг внутри `pattern_detector.process` — встаёт в очередь за паттернами;
   - б) свои asyncio-задачи в том же процессе;
   - в) отдельный сервис Railway — дополнительная оплата.
7. **Доставка:**
   - а) WS-канал;
   - б) ETag/304 — не работает через прокси;
   - в) поле `version` в ответе и перезапрос на границе 15m + 45 с, при возврате на вкладку и, пока идёт обновление, каждые 30 с.

## Решение

- **Тренд — 1Г.** Swing-точки — строгие фракталы, `swing_len = 2` на всех ТФ, как на графике.
  - Вход: «вверх» после HH + HL и закрытия выше последнего swing low.
  - Граница переходит на origin_swing каждого пробоя вверх.
  - Выход — закрытие за границей.
  - Повторный вход в то же направление — только после новой swing-точки.
  - «Вниз» — зеркально.
  - Первое событие окна показывается без типа («пробой»).
- **Направление старших ТФ — 2б.** EMA50/200, RSI14 (30/50/70), ATR14 с перцентилем за 200 значений (p20/p80) — это факты, они тренд не меняют. Отличие от bias плана 2.2 сознательное: bias — фильтр сигнальной стратегии, панель описывает структуру.
- **Сводка — без баллов и весов.**
  - Код определяет первое совпадение по H4 и H1.
  - 15m код не меняет, поэтому блокировка 15m по тарифу код не меняет.
  - Число совпадающих ТФ и строка BTC для альтов.
- **Область интереса — 3б.**
  - Ближайшая непробитая склеенная зона H4 по направлению старших ТФ, со стороны отката, не дальше 3 ATR H4.
  - Метки D1/W1 и по одной зоне H1 и 15m внутри.
  - Без триггера, без линии «зона перестаёт действовать», без цен входа, стопа и целей.
- **Уровни:** PDH/PDL и PWH/PWL. Поддержка/сопротивление по касаниям переносится в v1.1; при переносе эталоном станет Python, а TS-реализацию проверят по golden-файлам (как `scripts/indicator_golden.py`).
- **Деривативы:**
  - фандинг — перцентиль за 90 дней;
  - OI и цена за 24 ч;
  - явные статусы no_data и stale, никогда не ноль;
  - отдельный флаг выпуска.
  - Новостей нет до задачи календаря (3.19).
- **Параметры.** Свой `TopDownParams` с версией `topdown@1.0.0`, golden-файлом и строкой в `topdown_rules_versions`. `StrategyParams` и `latest_version()` не используются.
- **Хранение и расчёт — 4б, 5б, 6б.**
  - Секции пишутся только вставкой в гипертаблицу `topdown_sections` с input_hash и first_open_time.
  - Сводка и область — чистая функция при чтении.
  - Последние секции лежат в Redis.
  - Отсутствующая или устаревшая секция считается на месте без записи (ADR-0002).
  - Готовность: строка своего ТФ есть и `is_closed`. Исправление upsert `is_closed` идёт отдельной задачей.
- **Доставка — 7в.** Без ETag и без WS. Состояние вкладки и полосы шагов хранится в localStorage и sessionStorage, данные — в кэше модуля, потому что страница пересоздаётся при смене ТФ.
- **Выпуск.**
  - Флаг `TOPDOWN_PUBLIC`: до выпуска панель видят только admin и owner, с пометкой «предпросмотр».
  - Включение — после «принято» владельца на 20 примерах по каждому из наборов S1–S4 (S5 — для деривативов), утверждения текстов юристом и решения по тарифу.

## Последствия

**Плюсы:**
- Тренд меняется в 2–3 раза реже, чем по правилу плана 2.2, и не мигает на откатах.
- Граница «держится, пока нет закрытия за X» — проверяемый факт.
- Смена сигнальной стратегии не меняет панель, и наоборот.
- Повтор бит в бит: фиксированные окна, first_open_time, input_hash, проверки ValueError.
- Не нужен новый сервис Railway.
- Нативные 15m/1h убирают 30 тыс. строк 1m на секцию и дыры агрегатов.
- 15m не меняет код сводки, поэтому ограничение по тарифу безопасно.

**Минусы:**
- Есть третье определение тренда рядом с bias сигналов и `classify_trend` слоёв. Строка состояния переходит на тренд панели, слои графика пока нет.
- Тренд Г зависит от начала окна: проверено 40 из 40 срезов, а повтор точен благодаря фиксированному окну.
- Панель делит процессор с pattern_detector. При отставании от целей по свежести раннер выносится в отдельный сервис сменой команды запуска.
- Около 15 МБ в сутки до сжатия в `topdown_sections` (срок хранения 180 дней) и около 7 тыс. строк в сутки нативных 15m/1h.
- 100 примеров на проверку владельцем. Правка правила требует новой версии и повторной проверки набора.
- Направления по-прежнему могут прочитать как подсказку к сделке. Против этого работают коды без «вход/лонг/шорт», дисклеймер плана 8.2, тест запретных слов и проверка юристом.

**Пересмотреть:**
- после первой проверки примеров — `swing_len` для H1/15m (замер: 3 спокойнее на 30 %), порог 3 ATR для области;
- при задаче скринера — таблицу сводок;
- при задаче календаря — блок событий;
- для v1.1 — поддержку/сопротивление по касаниям;
- когда вернёмся к сигналам — нужно ли сигналам то же определение тренда (через новую версию стратегии и бэктест).
