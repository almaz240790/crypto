# ADR-0013. Сигналы — только для владельца до запуска продаж

Статус: принято (решение Fable по поручению владельца, ADR-0012). Дата: 2026-11-11.
Задача: «сигналы — только для владельца до запуска продаж»; план 2.11 (правила публикации), 3.4–3.5 (лента и
карточка), 3.10 (статистика), 4 (тарифы), 6.7 (статус-страница).

## Контекст

Владелец, дословно: «Ничего не нужно писать тестовый не тестовый все равно я буду один видеть продавать буду
когда все заработает не нужно всю техничку выворачивать на сайт чтоб я видел».

То есть: пока продажи не начаты, сигналы видит только он сам; публике и обычным пользователям не нужны ни
лента сигналов, ни их статистика (live, форвард-тест, бэктест), ни версии стратегии, ни плашки форварда, ни
подписи о комиссиях, ни строки движка сигналов на статус-странице. Ярлыков «тестовый режим», «бета» тоже не
нужно — раздел просто не виден.

До этого решения лента и карточки открывались любому вошедшему, `/stats` со всеми тремя вкладками и
`/v1/strategies` — всем без входа, письма и push о сигналах уходили всем, кто их включил, статус-страница
показывала «Движок сигналов» и «Трекер сделок» и правило «сигнал публикуется в течение 60 секунд».

## Варианты

1. **Один выключатель в API, по умолчанию выключен; всё о сигналах закрывается на сервере, сайт по ответу API
   прячет ссылки** (выбрано).
2. Удалить разделы сигналов с сайта до запуска продаж: владелец перестал бы видеть их сам, а возврат — новая
   разработка вместо одной настройки.
3. Прятать только ссылки на сайте: данные оставались бы доступны по адресу API любому, кто его знает.
4. Отдельный выключатель у сайта (переменная сервиса web): два места, которые надо переключать вместе;
   расхождение показало бы ссылки на страницы, отвечающие 404, или наоборот.

## Решение

Вариант 1.

**Выключатель** — `SIGNALS_PUBLIC` (настройка `settings.signals_public` в `apps/api/app/config.py`), по
умолчанию `false`. Открывает только явное `true` / `1` / `yes` / `on`; пустое значение или опечатка — закрыто,
опечатка пишется в журнал. Кто видит сигналы, решает одна функция `app.signals_access.signals_open(user)`:
выключатель включён — все (как до решения), выключен — только роли `admin` и `owner`.

**Что закрыто, пока выключатель выключен** (гостю и обычному пользователю — 404, как будто адреса нет;
admin и owner работают как раньше):

- API: `/v1/signals` (лента, обе области), `/v1/signals/summary`, `/v1/signals/{id}` с `/analysis` и
  `/candles`, `/v1/stats` (live, forward, backtest), `/v1/stats/trades`, `/v1/stats/export.csv` (и без входа
  тоже 404, а не 401), `/v1/stats/runs`, `/v1/strategies`. Эти адреса не попадают и в схему OpenAPI (`/docs`).
- Слой сигналов на графике (`/v1/chart/layers` → `signals: []`), события сигналов в сокете `/v1/ws`
  (роль — из подписанного токена при подключении).
- Письма и push о новых сигналах и событиях, дайджест — только admin и owner. Журнал остальных не
  сопоставляет сделки с сигналами (импорт, «Я вошёл»), не сравнивает их с системой, аналитика и еженедельный
  отчёт — без градаций сигналов и ошибок «по сигналу». Тестовый push ведёт на график, а не в ленту.
- Публичная статус-страница `/status`: без строк «Движок сигналов» и «Трекер сделок», их инцидентов и правила
  о публикации сигналов; общий статус — по оставшимся компонентам. Полный снимок монитора — во вкладке
  «Система» админки (`/v1/admin/system`, поле `monitor`), там же — состояние выключателя.
- Сайт: `/signals` и карточки — гостю 404 (сервер), вошедшему без прав — та же «Страница не найдена»;
  `/stats` (любая вкладка) уводит на открытую статистику паттернов `/stats/patterns`; нет ссылок и текстов о
  сигналах в скринере, вотчлисте, журнале, настройках уведомлений и API-ключей, онбординге, на странице
  отписки, в подсказке Heikin Ashi, в «Слоях» графика, в документации API. Шапка, меню, подвал, главная,
  тарифы и вопросы о сигналах уже не говорили (ADR-0006) — это закреплено e2e.

**Что открыто всем, как раньше**: график и его разметка, отработка паттернов и фигур (`/v1/stats/patterns`,
`/v1/stats/figures`, страница `/stats/patterns`), скринер, алерты, инструменты и цены, статус данных биржи,
свечей, уведомлений, паттернов, алертов и API.

**Как сайт узнаёт решение**: гостю API отвечает в `/v1/features` (`{"signals": false}`), вошедшему — полем
`signals` в `/v1/auth/me`. Серверные страницы спрашивают `/v1/features` (кэш 60 с), клиентские — берут поле из
профиля. Сервер не знает токена владельца (он есть только во вкладке браузера), поэтому статистику сигналов
admin и owner получают в браузере с токеном (`StaffStats`) и видят ту же разметку, что рендерил сервер
(`StatsView`). В админке — ссылки «Сигналы на сайте»: лента и три вкладки статистики.

**Код не удалён, а закрыт**: стратегия, трекер, комиссии и публикация сигналов не менялись — движок пишет
сигналы и трекер ведёт их как раньше, владелец видит всё. Тесты API, написанные до решения, идут с включённым
выключателем (`apps/api/tests/conftest.py`) и тем самым проверяют, что включение возвращает прежнее поведение;
матрица доступа гость / пользователь / admin / owner при выключенном — `tests/test_signals_access.py`.
На сайте прежние e2e идут с заглушкой API «сигналы открыты», новые — `e2e/signals.closed.spec.ts` со своей
заглушкой «сигналы закрыты».

## Как открыть сигналы для продажи

1. Проверить тексты, которые снова станут видны всем: лента и карточка, `/stats` (подписи областей, плашка
   форварда, подпись о комиссиях), онбординг, настройки уведомлений, документация API, тарифы (раздел 4
   плана), запрещённые формулировки (план 2A.10.6, 8). Юридические тексты — только с указания владельца
   (ADR-0012).
2. Задать `SIGNALS_PUBLIC=true` у сервисов API и воркеров (уведомитель шлёт письма и дайджест) на Railway и
   перезапустить их (схема `/docs` читает выключатель при запуске). Сайт подхватит сам в течение минуты
   (`/v1/features`), его переменные менять не нужно.
3. Проверить гостем и обычным пользователем: `/stats`, `/signals`, `/status`, `/v1/features` → `true`.

Вернуть как сейчас — `SIGNALS_PUBLIC=false` (или удалить переменную) и перезапуск.

## Последствия

- Посторонний не видит ни сигналов, ни их статистики, ни внутренней кухни движка; владелец — всё, как раньше,
  в том числе по ссылкам из админки.
- Пока выключатель выключен, обычные пользователи с включёнными письмами о сигналах их не получают; настройки
  в базе не меняются и заработают сами после открытия.
- Владелец видит статистику сигналов, только войдя на сайт под своим аккаунтом (вход в админку — отдельный
  сеанс, ADR-0011, на страницы сайта он не распространяется).
- Тексты о сигналах остаются в коде за выключателем: при правке их нужно держать актуальными, хотя публика
  их не видит.
- Витрина компонентов `/ui` (служебная, без ссылок, noindex) по-прежнему показывает образец таблицы сигналов —
  пересмотреть вместе с открытием продаж.
