`docs/backtests/2026-11-11-one-open-trade.md`, раздел «Данные локального прогона»). Форвард-сигналов и строк
`strategy_versions` в этой базе нет, поэтому раздел «Форвард» пуст, а пункты форварда — «не выполнено». Итог сверки

Ниже черты — вывод скрипта без изменений. Команда (выполнена дважды, файлы совпали байт в байт):

```
DATABASE_URL=postgresql+psycopg://platform:platform@localhost:5432/platform_test_t6 \
    uv run python scripts/live_gate_report.py --version 1.2.1 --to 2026-10-26 --now 2026-11-01 --jobs 3 \
```

`--now 2026-11-01` — граница локальных данных: так последние сделки периода успевают закрыться, как в
`scripts/backtest.py` (хвост 30 дней).

## Как запустить на production

Запускает человек: у Fable нет доступа к базе production, а форвард-строки доступны только admin. Скрипт выполняет
только `SELECT` (форвард — в транзакции только на чтение) и ничего не сохраняет в БД; надёжнее запускать его под
пользователем БД с правом только на чтение.

```
redis-cli -u "$REDIS_URL" get reconcile:last > reconcile.json
DATABASE_URL=<production> uv run python scripts/live_gate_report.py \
    --version 1.2.0 --symbols mvp20 --since 2026-10-26 --to 2026-10-26 --now 2027-01-25 \
    --jobs 4 --reconcile-json reconcile.json
```

- `--version 1.2.0 --symbols mvp20` — форвард кандидата 1.2.1. Версия 1.2.1 создаётся со статусом backtest и
  сигналов не пишет; её правила — это 1.2.0 на 20 парах MVP, а правило одной сделки действует по инструменту,
  поэтому сигналы 1.2.0 по этим парам совпадают с тем, что дала бы 1.2.1 (задача 11). Бэктест 1.2.0 на этих парах
  даёт те же сделки, что 1.2.1 (`docs/backtests/2026-11-12-v1.2.1-mvp.md`).
- `--since 2026-10-26` — отсчёт форварда 1.2 (ADR-0012). Без аргумента начало — переход версии в форвард по журналу
  смен статуса: заявки на смену статуса и записи аудит-лога о сменах без заявки (возврат заменённой live-версии в
  форвард, архивирование миграцией). У версии, созданной сразу в форварде до задачи 4, начало — создание строки.
  Раньше этого перехода `--since` начало не уводит; версия, которая в форвард не переходила, получает «не выполнено»
  в пункте о длине форварда, сколько бы дней ни прошло.
- Длина форварда — только время в статусе forward. Если версию вывели из форварда (в архив, в backtest или в live —
  live-версия пишет сигналы с областью live), форвард на этом кончается, и отчёт это пишет. Если версия выходила из
  форварда и возвращалась, перерывы в длину не входят, а пункт о длине при 3 месяцах и больше — «нужно решение
  человека». Например, если 1.2.0 заархивируют после выпуска 1.2.1 в форвард, этот запуск покажет форвард 1.2.0 до
  даты архивирования.
- `--to 2026-10-26` — бэктест кончается там, где начинается форвард.
- `--now` — момент отчёта; текущее время скрипт не использует. 91 день форварда (пункт «форвард не короче
  3 месяцев») набирается к 25.01.2027. Если запустить раньше, а закрытые свечи H4 в базе кончаются до `--now`,
  форвард считается до последней свечи — отчёт пишет это в «Параметрах» (строка «Граница данных») и в пункте о длине
  форварда. Инструменты, у которых свечи кончаются раньше остальных, перечислены там же, а пункт «форвард в пределах
  интервала» тогда — «нужно решение человека»: сигналы по ним могли не появиться.
- Форвард 1.2.0 с 26.10 по 12.11.2026 записывался без правила одной открытой сделки (задача 6). Скрипт прогоняет это
  правило по форвард-сигналам: подавленные в метрики не входят, их число есть в разделах «Коротко» и «Форвард», а в
  таблице сигналов они помечены. Если сделка подавленного сигнала шла и после 12.11, живой режим считал инструмент
  занятым и мог не записать сигналы, которые бэктест взял бы, — отчёт перечисляет такие сигналы, и пункт «форвард в
  пределах интервала» — «нужно решение человека». Отменённый вручную сигнал в 1m — 0 R, как в статистике сайта
  (план 2.10), а инструмент с момента отмены свободен, как в живом режиме; в H4-эталоне — результат без отмены, и
  пункт «форвард в пределах интервала» тогда — «нужно решение человека».
- Итог сверки: значение Redis-ключа `reconcile:last` (или поле `reconcile` из `GET /v1/admin/system`); вместо файла
  можно передать `--reconcile-redis`, тогда скрипт прочитает ключ сам по `REDIS_URL`. Без итога пункт «нет
  расхождений в сверке» — «нужно решение человека».
- Файл ляжет в `docs/backtests/2027-01-25-live-gate-1.2.0.md` (другое имя — `--out`). В нём есть таблица
  форвард-сигналов по одному в строке; это данные, которые на сайте видит только admin, — решить до коммита,
  оставлять ли её в репозитории.

**Почему на production числа будут другими.** Код тот же; отличаются входные данные. Локально нет открытого
интереса и long/short (их фильтры не блокируют сигнал и баллы не меняют), funding местами с пропусками, свечи — из
архивов, а не из REST, недели склеены из дней, у ICPUSDT пропуск в сентябре 2022. Отсюда лишняя сделка на 20 парах
(39 против 38 до 2025; после 2025 совпадение полное) и 6 лишних на 59. Это заметно в пункте 2.7: локально средний R
убывает A > B > C (у C всего 5 сделок), а в прогоне №6 у C 11 сделок и +0.49 R — больше, чем у B (+0.43), так что
на production этот пункт, скорее всего, будет «не выполнено». Сверить сделки построчно отсюда нельзя: списка сделок
прогона №6 на этой машине нет.

## Отличия форварда от бэктеста

1. **Исполнение: H4 против 1m.** Бэктест исполняет сделку по свечам H4 и при касании стопа и цели в одной свече считает стоп. Форвард и live ведёт 1m-трекер: он видит порядок касаний внутри H4-свечи, поэтому результаты законно расходятся. С бэктестом сравнивается H4-пересчёт форварда; 1m-результат показан рядом.
2. **Фильтр оборота работает только в форварде и live.** `forward.load_inputs` подаёт в движок средний дневной оборот инструмента (`instruments.avg_volume_30d` → `avg_daily_turnover`), бэктест — нет, и в бэктесте этот фильтр не срабатывает никогда (ADR-0013).
3. **Окно старших таймфреймов.** Бэктест подаёт всю загруженную историю D1 и W1, live — последние 400 дневных и 120 недельных свечей (ADR-0013). На сигнал это может повлиять только через самую старую свечу окна.
4. **Фильтры новостей, корреляции/BTC-bias, ликвидаций и разблокировок не получают данных нигде** — ни в бэктесте, ни в форварде. Между ними расхождения нет, с планом 2.5 есть: эти фильтры сигнал не блокируют и баллы не меняют.
5. **Правило одной открытой сделки** (задача 6). В бэктесте оно было всегда, при записи форвард-кандидата — только с 12.11.2026. Форвард-сигналы, которые оно подавило бы, в метрики не входят (в этом форварде таких нет). Правило в живом режиме смотрит на сделку по 1m-трекеру, бэктест — по H4: если по 1m сделка закрылась раньше, следующий сигнал в живом режиме будет, а в бэктесте нет. Лимитный вход (п. 3 задачи 6): сейчас везде рыночный вход, и расхождения нет. При лимитном входе оно появится: бэктест заранее знает, что лимит истёк, и инструмент им не занят; живой режим этого не знает и считает ожидающий лимит открытой сделкой — в live будут подавлены сигналы, которые бэктест взял бы (`docs/backtests/2026-11-11-one-open-trade.md`).
6. **Вход по цене закрытия сигнальной свечи** — и в бэктесте, и в форварде. Задержка публикации (десятки секунд после закрытия H4) и цена, по которой пользователь входит на самом деле, в результате не учитываются.
7. **Делистинги.** Бэктест идёт только по инструментам, которые есть в базе сейчас: пары, снятые с торгов, в историю не попадают (план 2.11 требует их учитывать — риск переоценки). Из списка 60 пар прогона №9 снят с торгов только EOSUSDT; в базе production его нет.
8. **Версия выбрана после просмотра результатов.** Параметры 1.1 подобраны walk-forward на 2022–2024; 1.2 — это 1.1 без лонгов, решение принято по результатам 2022–2026 целиком (прогоны №4 и №5, `docs/backtests/2026-10-25-longs.md`); 1.2.1 — 1.2 на 20 парах MVP, решение принято после прогона №9, где остальные 39 пар дали около нуля. Поэтому бэктест этих версий — не проверка на новых данных, часть преимущества может быть подгонкой. Форвард — первая проверка на данных, которых при выборе не видели.

## Как воспроизвести

```
uv run python scripts/live_gate_report.py \
    --version 1.2.1 \
    --from 2022-06-01 \
    --to 2026-10-26 \
    --now 2026-11-01
```

Одинаковые данные и аргументы дают тот же файл байт в байт: текущее время не используется, бутстреп идёт от зерна.
