# Версия 1.2.1: правила 1.2.0 на 20 парах MVP

Дата: 12.11.2026. Пакет «Сигналы», задача 11 (`docs/signals/2026-11-05-task-pack.md`). Решение о кандидате в live
(«1.2.1 на 20 парах MVP») принято по поручению владельца (ADR-0012). Числа — результаты на прошлых данных, а не
обещание результата.

## Что сделано

- В `StrategyParams` появилось поле `symbols`: инструменты, по которым версия выпускает сигналы (`None` — все
  активные). Список — часть версии: сменить его можно только новой версией. У 1.0–1.2 он `None`.
- Scheduler и cron `forward` не оценивают версию по инструменту вне её списка. Бэктест-скрипт у такой версии по
  умолчанию берёт её список, а из явно переданного отбрасывает всё, чего в нём нет.
- `trend-ob-retest@1.2.1` = 1.2.0 + 20 пар из `scripts/instruments_mvp.txt` (`engine.strategies.MVP_SYMBOLS`,
  тест сверяет их с файлом). Сама 1.2.0 не меняется. Новая версия создаётся со статусом `backtest`; в forward и
  live её переводят заявкой в админке.

## Проверка «бит в бит»

Два прогона `scripts/backtest.py` на одних данных, 01.06.2022 — 26.10.2026, рыночный вход:

```
uv run python scripts/backtest.py --strategy trend-ob-retest@1.2.1 --from 2022-06-01 --to 2026-10-26 --no-save --out v121.json
uv run python scripts/backtest.py --strategy trend-ob-retest@1.2.0 --symbols-file scripts/instruments_mvp.txt \
    --from 2022-06-01 --to 2026-10-26 --no-save --out v120.json
```

Сравнение с прогоном №6 на production (1.2 на 20 парах MVP): 70 сделок, PF 2.37, +33.5 R. Разница в одну сделку —
из-за входных данных: локально свечи из публичных архивов Binance, есть funding, но нет открытого интереса и
long/short (подробно — `docs/backtests/2026-11-11-one-open-trade.md`). Сравнение «бит в бит» с файлом сделок
прогона №6 отсюда невозможно: его на этой машине нет. На production его можно сделать той же командой.

По градациям (локально): A — 20 сделок, средний R +0.58; B — 46, +0.47; C — 5, +0.11. По годам: 2023 и 2026 —
в минусе (−0.78 R и −2.56 R), остальные годы — в плюсе.
